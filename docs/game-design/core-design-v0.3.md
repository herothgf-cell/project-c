## 0. 확정 사항 / 제안 / 보류

| 분류 | 내용 |
|---|---|
| 사용자 목표 | 기억 삭제로 대상의 행동 변화. 조작은 빠르게 이해, 풀이는 계속 고민. 기획→작은 플레이 버전→테스트→확장. |
| v0.3 유지 제안 | 대상은 남은 기억의 사실을 근거로 고정된 목적을 수행; 최신 근거 우선; 사건 전체 삭제; 전달된 기억의 소유자 독립; 삭제와 턴 실행 분리; 결정론·되돌리기·재시작. |
| v0.3 변경 제안 | ‘언제 지울지’를 살리는 실행 사이 기억 삭제 퍼즐 추가. 한 장면 안의 필요한 정보와 방해 정보를 함께 배치. |
| 신규 서사 제안 | ‘기록소의 마지막 밤’이라는 작은 사건과 결과를 기록하는 최종 선택. 엔딩 2종은 프로토타입용 검증안. |
| 이번 범위의 제한 | 목적·기본 능력은 삭제 불가. 기억 습득·전달은 시작 상태에 미리 기록, 실행 중 새 기억 생성 없음. 한 방이 한 퍼즐, 방 사이 기억/삭제 이력 비승계. |
| 미확정 | Godot 2D + GDScript는 우선 후보일 뿐 최종 결정 아님. 상업화, 플랫폼, 출시 규모·가격·일정 미확정. |

**기획 한 문장:** 대상이 가진 기억을 살펴보고, 필요한 과거는 남긴 채 행동의 흐름을 설계한다.

**초기 안내:** “기억을 지우면 남은 기억대로 행동합니다. 필요한 단서까지 잊게 하지는 마세요.”

## 1. 핵심 재미 가설

1. **믿음의 재배치** — 어떤 사실이 삭제된 자리를 다른 과거 기억이 메운다.
2. **손실을 계산하는 삭제** — 하나의 사건 카드에 여러 사람의 정보가 함께 들어 있어 일부만 지울 수 없다.
3. **삭제의 시점** — 지금 필요한 기억은 남겨 한 일을 먼저 끝내고, 이후 방해가 되면 삭제한다.
4. **소유자의 차이** — 어떤 대상이 원본을 잊어도 그 정보를 전해 들은 대상의 카드는 남는다.
5. **결과의 지속성** — 기억을 지워도 이미 배송한 물건·등록한 결과는 되돌아가지 않는다(명시적 되돌리기 제외).

처음 10초 안에 기본 조작의 목적을 이해하는 것을 목표로 하되, 성취 여부는 플레이테스트로 판정한다. 카드의 개수를 늘리는 것 자체를 난이도로 삼지 않는다.

## 2. 조작 루프와 플레이 정보

1. 퍼즐 방에 들어가 공개된 실제 상태와 목표·실패 조건 확인.
2. 대상 선택 → **목적**, **현재 판단**, **사용 중인 근거 카드**, 보유 기억 카드 목록 확인.
3. 카드 하나를 **삭제**(사건의 모든 사실이 함께 제거); 삭제만으로 턴 진행 없음.
4. 실행 전 ‘이전 판단 → 바뀐 판단’을 확인하고 필요하면 추가 삭제.
5. **한 단계 실행**: 각 대상이 행동 하나를 결정해 결과를 동시 반영.
6. 세계/배송 결과 확인 → 성공·실패 또는 계속. 한 단계 되돌리기 / 재시작 가능.
7. 성공 시 짧은 이야기 결과를 보고 다음 방으로 진행.

**정보 공개:** 현재 거주자 위치, 배송 순서, 기억 획득 순서, 기억 소유자·출처, 현재 판단·근거는 공개한다. 단 미래에 어느 카드를 언제 지워야 할지의 정답 경로는 공개하지 않는다. 플레이어는 숨겨진 정답을 ‘찍는’ 게 아니라 **공개된 정보를 조합·예측**한다.

**초기 조작 범위:** 클릭/터치로 카드 선택, 삭제, 실행, 되돌리기, 재시작. PC에서는 마우스 주 조작과 키보드 보조. 이동·물리 충돌·실시간 타이밍 없음.

## 3. 기억/행동 의미론 — 구현 계약 후보

- **실제 상태(World):** 방별 현재 인물 위치, 물건 배송 여부·배송 순서, 오배송 여부, 엔딩 보고 선택 등.
- **기억(Memory):** 특정 소유자가 얻은 한 사건; `id`, `owner_id`, `acquired_order`, `source`(직접 관찰/전해 들음), `facts[]`, `deleted`로 모델링. `facts[]`는 `(사람, 위치)` 항목의 집합.
- **사건 단위 삭제:** 카드 전체에 적용. 사실 하나만 고르지 못함. 다른 소유자의 독립 카드에 전파되지 않음.
- **최신 기준:** 해당 **소유자가 기억을 얻은 순서**(`acquired_order`), 사건의 발생 시각이 아님. 카드 화면에는 판단에 사용하는 순서를 표시. 소유자별 순서가 중복되지 않음.
- **근거 선택:** 사람별로 살아 있는 사실을 모아 `acquired_order`가 가장 큰 카드의 사실을 채택. 위치 정보가 하나도 없으면 `Unknown`. 다른 사람의 최신 카드가 해당 사람의 위치 판단을 덮어쓰지 않음.
- **목적:** 프로토타입에서 각 로봇은 정해진 수신자에게 봉인된 편지를 배송한다. 목적과 배송 능력은 기억이 아니라 고정된 기능.
- **행동:** 현재 순번의 수신자 위치를 안다면 그 방으로 편지 1개 발송. 모르거나 해당 로봇의 배송이 모두 끝났다면 대기. **대기해도 현재 순번을 건너뛰지 않음.**
- **인식 제약:** 불투명 배송구를 통해 발송하므로 로봇은 현재 거주자 위치를 직접 볼 수 없다. 플레이어가 보는 현재 상태와 로봇의 기억을 구분한다.
- **과거 사건의 진실성:** 기억 카드에 적힌 사건은 당시에는 실제로 일어났으나 이후 사람이 이동했을 수 있다. 퍼즐 실행 중 사람은 이동하지 않으며 직접 감지/새 기억 학습 없음.
- **결과의 독립성:** 이미 이뤄진 배송은 기억을 지워도 취소되지 않음. 오직 되돌리기/재시작만 해당 결과를 복원.
- **우선순위:** 별도의 ‘카드별 행동 우선순위’는 사용하지 않음. 대상의 목적 및 현재 배송 순번은 데이터로 고정하고, 정보 선택은 최신 획득순으로만 함. v0.1과 의도적으로 구별.

## 4. 턴 처리와 되돌리기

### 관찰/삭제
- 관찰과 삭제 중 시간 정지. 삭제마다 **독립적인 전체 상태 스냅샷**을 기록한다.
- 삭제 직후 새 현재 판단과 근거를 계산하지만 물리적 배송은 일어나지 않는다.

### 한 단계 실행
1. 실행 전 전체 상태 스냅샷 저장.
2. 모든 로봇이 **동일한 실행 직전 상태**를 읽어 각 1행동(발송/대기)을 결정.
3. 행동 결과를 한 번에 커밋. 프로토타입은 로봇 간 동일 물건·동일 장치를 동시에 조작하는 경우를 제외.
4. 오배송이 하나라도 발생하면 **실패 우선**. 오배송이 없고 공개된 필수 배송이 모두 완료되면 성공. 그 외 계속 진행.
5. 실패/성공 직후에는 다음 조작 대신 **되돌리기 / 재시작 / (성공 시) 다음 방** 제공.

### 되돌리기/재시작
- Undo 1회: **직전 삭제 1회** 또는 **직전 실행 1회**를 그 직전 스냅샷으로 복원. 연속 Undo 가능. 카드·믿음·진행 순번·세계·배송·실패/성공 상태·턴 번호 포함.
- Restart: 해당 방의 초기 스냅샷 복원, 그 방의 Undo 이력 초기화.
- **방 간 독립:** 다음 방에는 이전 방의 삭제와 로봇 상태가 전파되지 않음. 성공 여부 등 챕터 진행 기록만 캠페인에 남음.
- 목표 도달 불능 ‘진행 불가’는 자동 탐지 의무 없음. 관련 기억이 모두 없으면 대기하고 Undo/Restart로 복구 가능.
- 삭제 횟수/턴 수 점수, 제한시간, 실시간 행동, 이동충돌은 제외.

## 5. 프로토타입 범위

**포함:** 3개 독립 방, 로봇 A/B, 민아/준(현재 위치는 공개되는 수신자), 서·동·북 3개 배송구, 사건 기억 카드, 배송 애니메이션 간이 표시, Undo/Restart, 결과 패널, 마지막 사건 보고 선택 1개(2종 에필로그), 퍼즐 진행 저장.

**제외:** 자유 이동, 새 기억 생성/실행 중 정보 전달, 추측 AI, 신뢰도 수치, 실시간 타이밍, 전투, 아이템, 성장, 대규모 서사/대화 선택지, 분기별 추가 스테이지, 무작위 퍼즐, 모바일 네이티브·Steam 상용 패키징.

**스토리의 선택:** 카드 삭제와 실행 순서가 물리적 배송 성공/실패를 결정한다. 최종 보고 선택은 사건의 공개 여부와 엔딩 문구/기록을 바꾸나 **퍼즐의 정답 판정 자체는 바꾸지 않는다.** 퀘스트/다음 방 분기 대폭 증식은 금지한다.

## 6. 퍼즐 역할과 난이도

| 방 | 주요 학습 | 의도된 사고 | 허용된 실패 |
|---|---|---|---|
| P01 오래된 주소 | 최신 기억 삭제 → 예전 근거 복귀 | ‘삭제=반대 사실’이 아님 | 오배송, 위치 모름에 따른 대기 |
| P02 하나의 장면 | 한 카드 내 복수 사실, 실행 사이 삭제 | “지금은 필요하지만 나중에는 삭제” | 조기 삭제 시 정보 부족, 잘못된 방 발송 |
| P03 전해진 말 | 전파된 소유자별 카드는 독립 | 원본 삭제가 사본 삭제는 아님 | 한 로봇만 맞고 다른 로봇 오배송/대기 |

P01/P03은 학습 검증, P02는 시점·손실의 **핵심 재미 가설 검증**에 사용한다. P03을 대상 간 실시간 협업 퍼즐로 과장하지 않는다.

## 7. 콘텐츠와 UX 기준

- **고정 방 구조:** 서/동/북 방의 실제 거주 표시 + 배송구 + 로봇 목록 + 기억 카드 패널.
- **카드 표현:** `[획득순서] [출처] [사건문장]`; 카드 선택 시 사실별 인물 하이라이트. 삭제는 카드 전체로만.
- **판단 표시:** 수신자, 현재 위치 믿음 또는 ‘모름’, 실제 근거 카드 식별자. 삭제 즉시 전후 비교.
- **실행 결과:** 로봇별 ‘왜 어느 방으로 보냈는지’, 성공/오배송/대기를 순서대로 로그 표시. 물체 위치 변화가 이해 가능해야 함.
- **접근성 초안:** 색만으로 정답 구별 금지, 모든 중요한 상태를 텍스트와 아이콘 중복 표시, 카드 확대/포커스 가능성 고려, 과도한 시각 효과 배제.
- **힌트:** 처음에는 규칙 설명 + 근거 강조. 막힘 힌트는 ‘현재 대상의 다음 행동에 필요한 정보가 무엇인지’ 정도까지만 노출하고 정답 카드 번호는 바로 알려주지 않음.
- **스토리:** 짧은 챕터 도입/결말 대사, 마지막 공개 여부 선택. 후속 스토리 콘텐츠 상세 참조.

## 8. 수용 기준 및 검증

### 논리 검증(자동 테스트 계획)
- 최신 삭제 → 다음 순서 사실 채택; 전부 삭제 → Unknown.
- 한 장면 삭제 시 모든 사실 소실, 타인의 카드 유지.
- 같은 실행 직전 상태라면 같은 결정/결과.
- 실행 사이 삭제가 결과에 영향(P02 정답 경로).
- 한 로봇의 오배송 시 전체 실패; 미배송/대기는 성공 아님.
- Undo 1회가 삭제 또는 실행 직전 **전체 상태**를 동일하게 복원.
- Restart는 방 전체와 Undo 히스토리 초기화, 방 사이 이력 누수 없음.
- 마지막 선택은 엔딩 표시/저장만 변경, 이미 완료된 배송에는 소급 영향 없음.

### 사람 검증(가설이며 달성 주장 금지)
- 새로운 플레이어가 최소 안내 후 **10초 안에 '카드를 지우고 실행해 행동을 바꾼다'는 조작 목적**을 말할 수 있는가.
- 퍼즐 P02에서 실행 전 전부 삭제하지 않고 **순서의 이유**를 설명하는가.
- 실패 로그만 보고 왜 실패했는지 재현 가능한가.
- P03이 독립성 학습인지 단순 반복인지 확인.
- 적어도 5명의 첫 플레이 세션에서 막힌 지점, Undo/Restart 사용, 자발적 다음 문제 의사를 기록(목표 샘플; 실제 진행 전).

## 9. v0.1·v0.2 대비 설계 결정 기록

## 10. 열려 있는 의사결정

1. 스토리 톤·인물·마지막 기록 선택은 **신규 제안**이며 최종 확정 필요.
2. P02가 실제로 ‘아하’ 순간을 만드는지 테스트 필요. 만약 단순 삭제 순서 암기에 그치면 추가 레벨 제작보다 기억 관계 재설계가 우선.
3. 엔진·개발 언어·웹 배포 경로는 로드맵의 기술 준비 단계에서 최종 선정.
4. 브라우저/모바일 인터페이스 세부 레이아웃, 실제 소요 시간, 전체 퍼즐 수, 상업 모델은 보류.

**프로토타입 통과 문턱:** ‘3개 방을 완성했다’가 아니라, **같은 기억 규칙으로 플레이어가 삭제 대상뿐 아니라 삭제의 시점을 고민한다**는 관찰 근거가 생겼는가.
